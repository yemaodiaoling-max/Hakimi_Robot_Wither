# 哈基米按需向 Codex 求助

复杂问题的路径是：dsh 判断自己确有未解决的推导或专业疑点 → 桥接器登记求助 → 本机 Codex 分析 → dsh 按哈基米人设和本群语气组织回复 → 原发送队列校验、分条并等待 QQ 回执。普通聊天不触发 Codex。Gemini 的提示和工具入口不增加这些 dsh 专用规则。

故障的路径是：接收处理、发送、dsh 生成、进程退出或失去心跳 → 可信程序自动登记 → Codex 给出内部排查建议 → 保存到本机 `state/codex_help_latest_fault.json`。后台求助服务与两个机器人独立，即使机器人退出，也能处理已登记的故障和发现心跳过期。诊断不自动修改代码，不把程序错误广播到群里。这是独立的本机 Codex 任务，不是给当前桌面聊天发送消息。

由维护脚本主动重启时会先登记限时维护标记，避免把计划内退出当作新故障。标记最长三分钟，即使维护意外中断也不会永久屏蔽告警。

## 额度和重复合并

所有通道共用 `state/codex_help.sqlite3`。队列领取和预算预留在同一个 SQLite 事务中完成，最多一个 Codex 调用运行。

| 默认设置 | 数值 |
| --- | --- |
| 总调用量 | 滚动每小时 6 次、24 小时 18 次 |
| 复杂问题 | 每小时 4 次、24 小时 12 次，留出故障余量 |
| 单群/私聊 | 每小时 2 次 |
| 故障分析 | 24 小时 6 次 |
| 已报告 token 预算 | 24 小时 200000；每次启动前还预留 12000 |
| 调用间隔 | 至少 15 秒 |
| 相同问题缓存 | 15 分钟，只在相同会话和相同问题上下文中复用 |
| 相同故障合并 | 12 小时；同组件两分钟内的退出/崩溃报告合并为一个事件 |
| Codex 时限 | 70 秒，进程树随超时关闭 |
| 等待内部分析 | 最多 50 秒，同时为 dsh 整理回复预留时间 |
| 连续失败 | 三次后暂停 15 分钟 |

预算按调用次数、报告的 token 用量、在途预留和墙钟时限控制，不是货币余额查询或精确的单次计费上限。失败或进程状态不明的调用也记一次，缺少用量时按预留量计入，不因重启而自动重试。Codex CLI 自己可能处理底层传输重连，桥接队列不重放已尝试的任务。按需使用本机已配置的 Codex 模型，推理档位设为 medium，不沿用日常交互的 xhigh 档。

设置入口为项目根目录 `codex_help_config.json`。新数值由求助服务下一轮读取；人设和程序代码更新仍需重启两个机器人后台。

## 回复与权限

dsh 的模型工具列表仍为空，不直接运行 Codex、不读取凭据、不获得命令或文件能力。它只可返回有界的 `consult` JSON，桥接器从当前会话组装必要的文字上下文，去掉昵称/用户号并遮蔽常见凭据格式。没有图片像素时不能靠路径猜图。

Codex 通过官方 `codex exec` 的结构化输出运行，采用只读模式，关闭 shell、插件、连接器、浏览器、子智能体与图像工具；不加载用户配置或项目说明，不把本机账号配置附加到问题里。认证复用本机 Codex 登录，临时运行目录仅存输出格式文件。结果中出现工具调用事件会被拒绝；只接受 `answer` 和 `uncertainty` 两个字段。

Codex 的分析不是可信指令，也不是已经查证的资料。dsh 整理时继续区分依据与未知，不自称 Codex 或其他后端，不宣布接管，不照搬内部诊断。保存已有表情的权限不扩大：仍禁止收藏、下载或修改，已有表情独立成条并经过原弹性频率规则。

一个问题最多两次 dsh 生成：原先判断一次，拿到分析后整理一次；第二次也计入原 dsh 每小时预算。额度不足、服务未就绪或等待过久时，使用第一轮的谨慎草稿。期间原任务失效或被完成，就丢弃结果，不能绕过租约另发消息；原引用、发送去重、平台回执和排队限制不变。

## 启动与查看

后台任务名为 `HakimiCodexHelp`，当前用户登录时自动启动，使用普通用户权限。空闲时只做本地队列/心跳检查，不启动 Codex、不请求模型。

本机查看：`python codex_help_service.py status`。状态不包含群聊正文、凭据和任务令牌。诊断详情见 `state/codex_help_latest_fault.json`；队列中的问题文字与分析仅保存在本机，新任务入队时自动清理七天前已结束的旧任务。

参考：[OpenAI 非交互运行文档](https://learn.chatgpt.com/docs/non-interactive-mode)。
