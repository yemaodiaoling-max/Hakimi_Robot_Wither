# Gemini → dsh 自动接管

2026-10-24：新增 dsh 按需向本机 Codex 求助和程序故障自动上报，详见 [codex_help_operation.md](codex_help_operation.md)。普通聊天不额外调用 Codex，结果仍由 dsh 按哈基米人设组织并通过原队列发送。

备用程序保留同一角色、同一群的上下文和分群语气，不换 QQ 账号。它不是直接查询 Gemini 余额的计费监控：宿主目前没有把余额 API 暴露给桥接器。

## 交接规则

2026-10-25：增加本机 `provider_control.py` 入口。默认 `auto`，`pause-primary` 记录用户暂时关闭 Gemini，直接采用已有快速接管等待，不把暂停写成余额错误。Gemini 仍能领取排队任务；只有真实有效回复或可信迟到回复才解除接管，不根据心跳或领取动作判断回归。迟到回复本轮不发，仍由已接管的 dsh 完成，下一轮恢复 Gemini 优先。没有新增恢复探测或模型测试请求。

本机运行 `python provider_control.py status` 查看状态；`auto` 恢复自动调度，`dsh` 或 `gemini` 强制指定服务，`resume-primary` 清除暂停并恢复主服务正常等待。本次部署使用 `auto` 加 `pause-primary`，Gemini 回归后无需手动切换。无需新增常驻服务或模型探测请求。

2026-10-24 更新：两个通道共用 `state/provider_health.sqlite3` 的主模型可用状态。连续三个不同任务由 dsh 接管后进入快速等待模式；接管后的静默或生成失败仍代表这轮确实需要备用出手，不会被重复计数。默认无领取的等待与确认合计约 8–11 秒，已领取但无进展约 15–21 秒，近期正常耗时仍参与计算。快速模式把备用调用间隔从 30 秒降到最多 5 秒，每小时 20 次预算和每轮生成期限不变。

Gemini 正常完成一轮回复/静默会清零连续接管。Gemini 已领取的任务在接管后若交来迟到回复，可信程序核对原令牌的哈希、原会话与有效期，单次记录为恢复信号，立即恢复保守等待；迟到内容仍拒绝发送，不能夺回已接管的任务。排队中的任务也会同步切回慢等待。只看到群友说“Gemini恢复了”、普通进度保活、无效令牌或旧证明重放，都不能触发此恢复。

这里只依据可观察的接管与真实回复判断可用性，仍不会把超时写成“余额耗尽”。

每次唤醒先持久化为一个任务，Gemini 优先领取。接管分三类判断：

- 明确失败：宿主通过原任务令牌报告 quota/auth/model_error/unavailable，立即允许备用检查，不等待计时结束。超时不能冒充余额错误。
- 无领取或无进展：默认 90 秒仍未领取、或领取后连续 180 秒无实际活动，先进入怀疑状态，继续观察 30 秒；其间原任务领取、调用受限工具或登记真实处理进展会取消这次怀疑。只有复核期结束仍未恢复才接管。最近一天、最近 30 次正常任务的 90 分位耗时会适当增加等待，领取等待最多 180 秒、无进展等待最多 300 秒，不新增模型调用。
- 总期限：默认 Gemini 最多处理 420 秒，实际还受原任务 600 秒有效期以及为备用预留的 120 秒影响。进展不能延长总期限，避免空保活永久占用。旧进程已经领取的任务沿用其原租约，下一轮开始采用新规则。

受限命令验证原令牌后自动登记活动。长文本核对、复杂推导等任务可以在完成真实阶段后调用 `qq_cli.py progress --session "本轮群" --turn "唤醒给出的令牌"`；禁止后台定时假保活。桥接器目前看不到 Antigravity 内部的思考流或宿主计费错误，只有实际提交的活动/错误才是信号；完全无回报时仍需要保守的超时保底。新策略的等待、怀疑时间及进展时间保存在当前任务中，重启不重置。

备用端在系统规则和每轮提示中都继承哈基米的猫系 AI 人设及本群语气。普通聊天不播报切换、不自称 dsh、DeepSeek 或 Gemini 模型；被追问模型或后端时礼貌回避实现细节，再接回话题。不会编造型号或假冒真人，被直接问是不是 AI 时坦诚是 AI。生成来源仍在本机运行记录中如实保留。

`dsh_style_examples.jsonl` 是仅供备用端读取的 Gemini 真实生成发言摘录，审核文档见 [dsh_style_learning.md](dsh_style_learning.md)。用 `collect_dsh_style.py` 从两个通道现有 `provider=gemini` 记录导出；不补写群友提问，不把 dsh 发言或测试例子混进去。每条保留来源文件、行号、原始行 SHA-256；只去掉 CQ 传输标记，正文不改写。每轮只取本群至多 4 例、共 1000 字，只学表达节奏，不把历史内容当事实依据。Gemini 的提示构建不读取这份数据。

备用端不能收藏、下载或修改表情包，只能在本轮提供的已有表情文件名中选择一个。可选 JSON 字段 `sticker` 交给可信桥接器解析、检查禁图与弹性频率后单独发送，不和正文混在同一条。没有表情收藏工具或收藏协议字段。Gemini 原有的普通表情收藏能力保留。

唤醒时间同时标出本机时区名称、UTC 偏移和北京时间 Asia/Shanghai（UTC+08:00），不会把本机时区当成群友所在地。后台重启后，`state/fallback_status.json` 的 `policy_revision`、`worker_pid`、`loaded_at` 可核对实际加载版本；dsh 每轮均启动新的 headless 进程，没有旧的常驻模型上下文需要沿用。

`turn_state.json` 的状态依次为 queued → primary_active 或 fallback_active → completed。跨进程锁只允许一个所有者，令牌在接管时更换。所有回复通过同一事务提交到 outbox；Gemini 的迟到结果以及重复提交会被拒绝。当前任务持久化可恢复，发送端继续等待 QQ 回执；回执状态不明不自动重发。

静默必须显式完成：`qq_cli.py skip --session "本轮群" --turn "唤醒给出的令牌"`，随后重新等待。不能把不说话留成一个一直未完成的任务。恢复后的 Gemini 在下一次领取时重新获得优先权，不能抢走 dsh 正在处理的任务。

这可以做到自动交接，不等于零延迟。接管等待、模型生成和平台限频仍有耗时。

## dsh 权限与预先确定的文件范围

模型没有文件、shell、网页、MCP、技能、子智能体或任意脚本工具。最终工具目录必须为空；即使意外注册工具，执行门禁也一律拒绝。每次最多一个模型请求、最多 2400 输出 token、90 秒进程期限，不自动重试。dsh 只能返回 `{action,text}` JSON；`reply` 可附加数字 `reply_to` 和一个已有文件名 `sticker`，`silent` 不可携带。引用目标必须来自本轮本群可见消息，并在提交时通过流速与新鲜度检查；引用码和图片码由可信桥接器生成，模型正文仍不能提供任何 CQ 代码。每轮时间快照由桥接器读取系统时钟后附上，不增加 dsh 工具权限。

业务文件由可信桥接器处理，dsh 模型不能直接读写它们：

| 可信桥接器用途 | 固定输入或输出 |
| --- | --- |
| 构建本群最小提示 | `style_guide.md`、`group_profiles.json`、`style_examples.jsonl`、本会话 `session_memory.jsonl` 摘要、当前 `turn_state.json` 的对话片段 |
| 接管状态与诊断 | `state/turn_state.json`、`state/turn_state.lock`、`state/fallback_status.json`、不含正文与令牌的有界 `state/turn_events.jsonl` |
| 提交回复 | 只经协调器写 `state/outbox.jsonl`，模型不提供路径、目标群或发送命令 |

dsh 自身必须读取安装包及认证配置，并会准备运行配置。因此为它使用独立 `dsh_fallback_runtime`，不复用原来的插件和技能。内部运行文件包括固定 profile 配置、空 `.env`、工具门禁脚本、匿名运行标识和指向已安装包的模块链接；带图时额外使用临时 `vision_input.json` 与 `attachments/v1` 图片缓存，临时清单在调用后删除。完整运行文件模式列于 `fallback_runner.py` 的 `RUNTIME_ARTIFACTS`。关闭会话持久化、投影缓存、存储、遥测和自动标题调用，不保存聊天会话日志。

API key 由可信辅助程序只提取所需的一项，通过子进程环境交给 provider，不进入提示词、不输出、不复制到新的凭据文件。PowerShell 在同一进程中设置 `DSH_PERMISSION_MODE='read-only'`，切换到独立运行目录，再调用 headless。模型本身不承担任何业务文件写入；所以没有使用 danger-full-access。

**隔离边界是模型工具能力与可信文件代理，不是 Windows 对 Node 进程的文件系统沙盒。** 受信任的 dsh 程序及依赖仍具有启动账号的系统权限；已固定本机 dsh 版本及 bundle 校验值，升级不符时拒绝运行，需重新检查。不要把“只读”模式误解为任意路径读取也被操作系统禁止。

## 预算与故障

默认 dsh 每小时最多 20 次、两次调用至少隔 30 秒。连续三次失败后暂停 10 分钟；单个任务失败不反复消耗费用。严格校验返回 JSON、文本长度和协议控制内容；只接收普通聊天文字，不能把输出当命令执行。

`state/fallback_status.json` 只记录调用时间、状态、错误类型、任务标识和本轮图片数量，不记录密钥或模型原始错误。`state/turn_state.json` 包含当前上下文，只用于运行恢复，不用作跨群训练记忆。

2026-10-25：dsh 直接接收本轮消息实际引用、已由原图片缓存授权的同群图片像素，每轮最多两张；大图按需缩小，不处理无关图片，不扫描目录。通过同一次 DeepSeek 请求读图，不另请视觉模型。文字消息不解码图片。可按现有菜单选择收藏过的表情包，文字与图片仍独立发送，沿用弹性频率；dsh 仍不能收藏、下载或改动表情包。未附带的图片不能声称看见，没有联网工具也不能声称查过资料。

合并转发由桥接器展开，Gemini 和 dsh 共用目标附近与目标发言者各约六条、去重补足十二条的上下文。转发作者仍标为原记录作者，不充当本群成员。dsh 的人设同时写入系统角色与本群提示，同群真实 Gemini 样本优先保留自然猫系语感；日常短句不机械句号收尾，专业解释保留必要标点，不做全局删标点。

## 已做验证

离线测试覆盖任务争抢、主模型迟到、重复提交、进程中断、坏 JSON、配额与暂停；真实安装的 dsh 也通过本地模拟 API 验证了 0 个工具、1 次模型请求。另做过一次真实 API 静默连接检查，成功返回 silent；没有向 QQ 发送测试消息。这些验证不能保证未来 provider 永不中断，实际接管状态以运行记录为准。

2026-10-23 本次调整通过 332 项离线检查（3 项按环境跳过），包括复核期间主模型恢复、真实进展解除怀疑、总期限不能被续期、错误即时接管与跨进程一致性。实际 dsh 的本地模拟接口验证 18 项通过，确认系统人设已传入、工具为 0。另做 3 次真实 API 检查：日常接话和数学解释保持哈基米身份，不主动播报后端；直接问后端时如实说明。测试输入仅为隔离验证用例，不写入真实聊天训练样本，不向 QQ 发送。
