# B站视频观察

Gemini 收到本轮可见的 B站链接、短链接或视频卡片后，可以使用现有工具入口 `bilibili_video`。程序解析视频流，按时长取六个分散时间点，优先复用本地 FFmpeg，仅用两个低优先级、单解码线程的短进程抽帧，不下载全片、不常驻浏览器。有效帧可能少于六张；只有至少两张真实帧时才交给模型。

- **Gemini 值班**：`python qq_cli.py tool --session 本轮群 --turn 本轮令牌 --name bilibili_video --url "本轮B站链接"`，无需在PowerShell里转义JSON。由 dsh 看两张带时间和 F 编号的抽帧拼图，返回基本观察与最多两张关键帧的本机路径；Gemini 必要时看关键帧，再用同一哈基米人设回答。只接受当前上下文中的视频链接。六小时内复用有效抽帧与观察缓存。
- **dsh 接管**：桥接器为当前回复目标准备同样的抽帧，在原本那一次 dsh 请求中附上，dsh 直接根据画面回答；不用先看视频再调用自己一次。可返回 `video_frames` 选择最多两张 F1–F6 原帧，桥接器作为普通图片独立发送，不当作收藏表情，也不增加收藏权限。

默认只观察实际抽到的画面与标题简介，**没有取得音轨、字幕，也不是全片逐帧观看**。不能据标题推断台词、完整论证或未采到的动作。失败会明确标为未取得画面，不生成假观看总结。长课程或依赖对白的问题，后续可以按需求再扩展字幕或指定时间段。

## 登录与依赖

用户已授权复用 Edge 的 B站登录并仅加密保存该站点凭据。此机 Edge 的浏览器加密格式不被解析库支持，因此改用 B站官方扫码登录：`python bilibili_login.py --qr` 生成官方二维码，手机确认后运行 `--poll`。只保存 `.bilibili.com` 和 `b23.tv` 的站点凭据到 `state/bilibili_cookies.dpapi`，由当前 Windows 用户加密；调用解析器时短暂创建站点 cookie 文件，结束后删除。模型不接触凭据，不把凭据值输出到日志。

登录过期时重新扫码，不必关闭 Edge。`video_tools_config.json` 指定本机 FFmpeg，依赖列在 `requirements-video.txt`。目前仅处理正常可访问的视频，不处理付费或地区无权限的内容、直播及整个合集。

验证记录：`state/video_pipeline_live_validation.json` 是合成短片经过真实 FFmpeg 和 dsh 的双路径验证；`state/bilibili_real_video_validation.json` 是真实站点验证。两者均不向 QQ 群发送测试消息。
