# 哈基米跨端人设与记忆：实施决策

日期：2026-11-01。用户明确授权迁移 QQ 哈基米人设，定时交换摘要，保留两端独立，并创建本地 Git 仓库。

## 同一个哈基米，两条独立活动记录

继承 QQ 当前核心人设，B 站只增加观看与直播的环境说明。核心人设作为可版本管理文本；源文件完整快照和真实记忆均在忽略 Git 的 state/private 下。QQ 工具命令、群号、个人关系、账号秘密不会混进通用核心人设。身份文案允许两端把共享观看摘要作为“我的 B 站经历”自然回忆，例如“我刚才在 B 站看了群友028”。这不要求每次向群友解释内部架构；内部仍保留是 B 站端观察、观察区间和缺失内容，不能把未处理片段补写成亲历。

两个实例有独立运行状态、观看/对话上下文、原始数据库、预算与故障边界。同步仅增加有来源的摘要层，不合并原始库，不改变 QQ 既有跨群权限逻辑，不让同步包直接控制工具。

## 双向交换

| 方向 | 默认频率 | 内容 | 长度与行为 |
|---|---|---|---|
| 视频哈基米 → QQ 哈基米 | 30 分钟检查 | 已实际观察的内容、片段要点、感受、观看范围 | 新增时才传；无观看证据不造摘要 |
| QQ 哈基米 → 视频哈基米 | 2 小时检查 | 关键词检索明确可分享的知识、兴趣、自我反思，轮换并随机抽样 | 每轮最多6条、单条200字、正文总1000字；不复制私聊原文、个人档案或工具凭据，导入摘要不再次出口 |

这些是应用内部定时任务，由独立轻量服务唤醒，和 Codex 聊天自动化无关。默认压缩为确定性筛选、去重、摘取和字符截断，没有新增压缩模型调用。它属于有损摘记，不是经过模型理解重写的摘要；原文保留在来源端。注入摘要仍会占正常回复的上下文token，因此按相关性筛选且限制1000字。以后若需要更自然的整理，另接低频模型并计入既有预算，不能悄悄增加调用。

QQ关键词从固定兴趣词和符合共享规则的正文中提取，轮换时有15%机会随机探索；结果排序也带随机性，优先未读与新修订，同一版本24小时内不重复选取。没有符合条件的新条目时空轮，不制造新发现。视频端在独立导入摘要库记录来源、修订、首次接收时间及检索词，不能当作B站观看证据。选片和点播理解优先使用最近读入，并轮换旧兴趣线索：最多3条，每条最多180字、正文总500字、完整JSON最多1000字符，与真实观看high/low兴趣共同影响选择。原有直播优先、探索过滤、预算与评论门槛不变。

完整可共享集合只用于核验删除/过期；随机没抽到不会撤回旧记录。扫描超过1000条安全容量会失败并保留已有记忆。续期仅处理当轮选中的少量条目，避免批量续期突破上限。日志不写记忆正文或检索词。

## 最小数据契约

摘要包有协议版本、稳定包ID、来源端、接收端、创建/过期时间、原记录ID与版本、事实列表、出处、观察范围、压缩标记和校验和。新版本生成新包；同包重试只接收一次。校验和用于发现损坏，不充当来源认证；部署采用本机权限隔离或已校验主机身份的 SSH，不开放公网同步端口。

端点在本地配置中固定，不能由不可信内容选择。导入记录永不作为本端原生记录再次导出，避免两端反复强化同一摘要。撤回通过墓碑传播；删除或过期的摘要不再召回，不能因重试旧包复活。跨端检索有独立字符预算，默认最多1000字，供人设装配器作为数据注入，不覆盖系统人设或程序策略。

SQLite 保存 inbox/outbox、已见包、同步游标、到期时间及重试状态。发送确认与游标推进按持久状态协调；网络/进程失败后可以恢复；日志只含状态、数量、包ID和错误类别，不打印记忆正文。服务只在到期、有新内容或需重试时工作，空闲无模型调用。

## 轻量项目边界

保留已有 domain / orchestrator / platform / media / cognition / memory / policy / runtime 分层；新加 persona（人设装配）、sync（平台无关摘要协议与调度）、integrations（QQ当前源码/数据库的兼容适配）。deploy 保存部署服务描述，scripts 保存运维入口。QQ接口依赖封装在适配层，不把QQ整套守护、督导、图谱、向量服务或插件搬来。

QQ端优先旁路摘要库与小型上下文接入，不迁移或改写原始QQ记忆schema。接入前核验实际服务运行目录，备份需要更改的源码，提供回滚。B站观看链路尚未接通时，B站出口应保持为空；可以先验证QQ→B站摘要同步和双方摘要读取，不冒充已经刷过视频。

## 验收

- 核心人设能装配，数据摘要不能替换系统身份；字符预算、来源标记、缺失观察得到保留。
- 同包重试、服务重启不重复导入；导入内容不回传；来源隔离、过期、删除及旧包重放均受测。
- 空源和未到期只返回状态；模拟中断不会丢失待确认数据；两端故障互不暂停主机器人。
- 真实只读源导出只记录数量和摘要长度；服务器定时任务健康可核查，QQ上下文实际能读到摘要层。
- Git只跟踪源码、通用人设、样例配置、测试和文档；凭据、真实记忆、运行数据、源人设快照不入库。先建立本地仓库与首个提交，未指定远程仓库时不发布。

### 视频回忆的来源（2026-11-02）

原生 evidence 与 notes 的检索结果带 `source_refs`，从记录自身的 account/platform/kind/identity scope 派生；不跨账号或视频合并。真实 BV（`BV` 加 10 位字母数字）可展示对应 B 站视频链接，未知标识只保留原始引用，不推测或缩短链接。直播仍使用独立直播引用。

QQ 快照在已有 `[B站·视频]` 标签后前置 `来源：BV…`，并在 `source_refs` 补充对应视频公开链接。这是从历史真实引用派生的展示字段，不修改源事实或 revision，不增加模型调用。现有线上 QQ helper 只按 summary 检索，也可立即按 BV 召回；裁剪正文时前置 BV 和独立引用仍保留，无须重启 QQ。新版 helper 还会检索 source_refs，并提示回答来源时使用已有 BV/链接。

同步门槛保持不变：只有原生、同账号、实际媒体 observation、非空覆盖区间的观看证据进入桥接，候选标题、选择记录及未知 BV 不产生虚构观看来源。
